# The_Gaming_Room

The client, The Gaming Room, wanted to expand their existing Android game to reach larger audience. They wanted a cross platform web-based multiplayer game called Draw It or Lose It.

When developing this document I was able to meet the client requests and translating it into technical requirements such as running one game instance, managing multiple teams, creating unique names, and being cross-platform accessible.

What I found helpful of the design document when developing the code was the UML diagram because it helps with understanding the relationship between the different classes and knowing where to implement the Singleton pattern.

If I had to choose one part of the document to revise, I would pick my recommendation section. I would improve it by adding more in depth comparison of the different systems and why I chose to recommend Windows and focus more on how it meets the clients requirements.

I interpreted the user's needs by translating the clients requirements into specific software design and functions. For example one of the requirements was running one game instance so a Singleton pattern was implemented into the designated classes. It's important to understand user needs because it helps when designing the Software Design Template and UML diagram. Which in turn helps developers in coding software that is functional, scalable, and easy to maintain.

I approached the software design process by first analyzing the client's requirements then implementing them into the software through object-oriented design principles such as inheritance, composition, and encapsulation. In the future I will continue using UML diagrams because they provide a clear path that is very helpful during the codign process.
